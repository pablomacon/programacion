Pensar como Programador

Antes de escribir código, necesitamos entender el problema. En este recurso vamos a mirar cómo se relacionan el usuario, el programa y el programador.

1

¿Quién participa?

Tres roles distintos: quien usa, quien ejecuta y quien crea instrucciones.

El usuario usa el programa. Ingresa datos y mira el resultado.

El programa ejecuta instrucciones. No inventa: sigue pasos.

El programador crea las instrucciones para que el programa funcione.

Idea clave: el usuario entrega datos; el programador entrega instrucciones; el programa ejecuta.

Actividad para explicar en video

Mirando la imagen, explicá con tus palabras o en lengua de señas:

  • ¿Quién usa el programa?
  • ¿Quién crea instrucciones?
  • ¿Qué hace el programa?
2

El programa no adivina

Si los datos o las instrucciones son confusos, el programa no puede resolver bien.

Un programa no entiende intenciones. Necesita datos claros e instrucciones exactas.

Cuando falta información, el programa no puede continuar o devuelve un resultado confuso.

Idea clave: programar es decirle al programa qué hacer, paso por paso, sin suponer que “ya sabe”.

Pregunta para responder

Observá la imagen y explicá:

  • ¿Qué está confuso?
  • ¿Qué necesita el programa para funcionar?
  • ¿Qué debería corregir el programador?
3

Entrada y salida

Entrada es el dato que entra. Salida es el resultado que vuelve al usuario.

👤 Usuario ➜ 📥 Entrada ➜ 💻 Programa ➜ 📤 Salida ➜ 👤 Usuario

Actividad para explicar en video

Mirando la imagen, respondé:

  • ¿Qué dato entra al programa?
  • ¿Qué hace el programa con ese dato?
  • ¿Qué resultado sale?
4

El algoritmo: pasos ordenados

Un programa funciona siguiendo instrucciones en orden.

Un algoritmo es una secuencia de pasos para resolver un problema.

El orden importa: si cambiamos los pasos, el programa puede fallar o mostrar algo incorrecto.

Idea clave: primero se pide el dato, después se ingresa, luego se guarda/procesa y al final se muestra el resultado.

Desafío

Explicá la historieta usando conectores de orden:

  1. Primero...
  2. Después...
  3. Luego...
  4. Al final...

Para cerrar

Programar no es solo escribir código. Primero hay que entender el problema, reconocer quién usa el programa, qué datos entran, qué instrucciones se ejecutan y qué resultado debe mostrarse.
